# API contract

All timestamps are ISO 8601 UTC strings. Generation and power errors use MW. Null means unavailable, never zero. Defaults are decision_date=2026-01-15, cutoff=09:00, from_date=2026-01-01, to_date=2026-01-31. Supported decision dates are January 1 through 31. Delivery is the next London calendar day. Expected hourly intervals are 24 for every supported day. Cutoff accepts HH:MM, from 00:00 through 23:59.

## GET /api/replay

Query parameters are decision_date, cutoff, include_actuals=false.

```json
{
  "decision_date": "2026-01-15",
  "delivery_date": "2026-01-16",
  "cutoff": "09:00",
  "cutoff_time": "2026-01-15T09:00:00Z",
  "include_actuals": false,
  "expected_hours": 24,
  "forecast_hours": 24,
  "matched_hours": 0,
  "mean_forecast_mw": 12345.0,
  "peak_forecast_mw": 13000.0,
  "min_forecast_mw": 11000.0,
  "latest_publish_time": "2026-01-15T08:30:00Z",
  "oldest_publish_time": "2026-01-15T08:30:00Z",
  "metrics": null,
  "intervals": [{
    "start_time": "2026-01-16T00:00:00Z",
    "forecast_mw": 12345.0,
    "publish_time": "2026-01-15T08:30:00Z",
    "forecast_source_id": "WINDFOR-2026-01-15",
    "actual_mw": null,
    "actual_source_ids": [],
    "actual_half_hours": [],
    "error_mw": null,
    "status": "forecast_only"
  }]
}
```

Status is one of matched, forecast_only, missing_forecast, missing_actual. When include_actuals is false no actual fields or metrics expose hindsight values. When true actual_half_hours includes both contributing actual objects with start_time, publish_time, generation_mw, source_id. An incomplete pair may be shown in actual_half_hours but actual_mw and error_mw remain null. No later forecast fills a gap. Per-target vintage selection may use multiple publications.

## Metrics object

```json
{"n":24,"mae_mw":1000.0,"rmse_mw":1200.0,"bias_mw":500.0,"wape_pct":7.5,"p90_abs_error_mw":1800.0,"mean_actual_mw":10000.0,"mean_forecast_mw":10500.0}
```

All values except n are nullable for n=0. WAPE is also null if summed actual power is zero. Error is forecast minus actual. Positive bias means overforecast wind and potential additional procurement exposure, not a calculated customer purchase. Use linear-interpolated 90th percentile of absolute matched errors. Forecasts are treated as representative of [start_time, start_time+1h). This is an explicit alignment assumption, not an asserted source interval-average guarantee. Pair against the mean of both WIND actual half-hours. Hourly errors are proxies under this assumption, with no interpolation.

## GET /api/accuracy

Query parameters are from_date, to_date, cutoff. Validation rejects a reversed range or any decision outside January 2026.

```json
{
  "from_date":"2026-01-01","to_date":"2026-01-31","cutoff":"09:00",
  "expected_hours":744,"forecast_hours":744,"matched_hours":744,
  "metrics":{"n":744,"mae_mw":1000,"rmse_mw":1200,"bias_mw":500,"wape_pct":7.5,"p90_abs_error_mw":1800,"mean_actual_mw":10000,"mean_forecast_mw":10500},
  "daily":[{"decision_date":"2026-01-01","delivery_date":"2026-01-02","expected_hours":24,"forecast_hours":24,"matched_hours":24,"metrics":{"n":24,"mae_mw":1000,"rmse_mw":1200,"bias_mw":500,"wape_pct":7.5,"p90_abs_error_mw":1800,"mean_actual_mw":10000,"mean_forecast_mw":10500}}],
  "errors":[{"start_time":"2026-01-02T00:00:00Z","forecast_mw":10500,"actual_mw":10000,"error_mw":500}]
}
```

Pooled metrics calculate across all matched hourly errors, never average daily RMSE. Actuals are retrospective and may include revisions. Accuracy is descriptive in-sample evaluation, never a prediction interval or decision-time backtest of a fitted risk model.

## CSV exports

GET /api/replay.csv accepts the replay parameters. GET /api/accuracy.csv accepts accuracy parameters. Both call the same analysis functions. Export each interval, including gaps, the cutoff, selected forecast issue time, source identifiers, actual half-hour evidence when included, status, and snapshot SHA256. Send Content-Disposition attachment with a descriptive filename. Snapshot identity is included as a column so the CSV can be audited independently.

## Errors

Invalid parameters return HTTP 422 with a detail field. Missing bundled data returns HTTP 503 with an actionable detail field. GET /api/health returns status=ok and the snapshot hash after successfully loading and validating the snapshot.
